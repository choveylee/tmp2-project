建议顺序
明确第一版范围。先定 MVP：支持创建知识库、上传文件、解析入库、检索、问答，不先做复杂权限、复杂工作流、多租户隔离细节。验收标准：你能清楚说出“第一版能做什么、不能做什么”。

定义业务对象。先把核心对象定下来：knowledge_base、document、document_version、chunk、file_object、ingest_job、chat_session、chat_message。验收标准：每个对象的用途、状态流转、主键关系都明确。

初始化 MySQL 表结构。把知识库、文档、版本、切片、任务、会话、消息这些表真正建起来。验收标准：能在数据库里看到完整表，能手工插入一条知识库和文档记录。

初始化 SeaweedFS 存储规范。约定 bucket、对象 key 命名规则、原始文件路径、解析中间文件路径。验收标准：能上传一个测试文件，并能在 SeaweedFS 中找到。

初始化 OpenSearch 索引。执行索引初始化脚本，确认 mapping、分词器、向量字段、读写别名都创建成功。验收标准：kb_chunks_v1、kb_chunks_read、kb_chunks_write 正常存在。

定义文档导入流程。先把“上传文件 -> 写 MySQL 文档记录 -> 写 SeaweedFS -> 投递 Redis 任务”这条链路设计清楚。验收标准：上传一个文件后，数据库、对象存储、任务队列里都能看到对应记录。

实现上传接口。先做一个最小 API：创建知识库、上传文档、查询导入状态。验收标准：前端或 Postman 可以完成一次上传，并拿到文档 ID。

实现任务队列与 Worker。用 Redis 承担异步任务，至少拆成 parse、chunk、embed、index 四类任务。验收标准：上传文件后，不依赖手工触发，任务会自动往下流转。

实现文档解析。先接 Tika，把 DOCX、TXT、HTML、文本型 PDF 跑通；再补 PaddleOCR 处理扫描件、图片、图片型 PDF。验收标准：同一个文档最终能拿到“可入库纯文本”。

定义解析回退策略。明确什么时候走 Tika，什么时候补 OCR。常见规则是：先 Tika，如果结果为空、很短、或者判断为扫描件，再走 PaddleOCR。验收标准：至少 3 类文件都能正确选择解析路线。

实现文本清洗。把解析结果做基础清洗：去空白、去异常控制字符、保留标题层级、保留页码信息。验收标准：数据库里的文本可读，不是脏乱原文。

实现切块逻辑。使用你前面已经定下的 Eino splitter，把文档按标题或段落切块，并保存 chunk metadata。验收标准：一个文档能稳定切成多段，每段有 chunk_no、heading_path、token_count 等信息。

实现 embedding。用 Ollama + bge-m3 对 chunk 生成向量。验收标准：每个 chunk 都能生成 embedding，失败能重试，成功后状态更新。

实现写入 OpenSearch。把 chunk 文本、metadata、embedding 写入 kb_chunks_write。验收标准：OpenSearch 里能查到文档 chunk，向量字段存在。

实现检索接口。先做最小搜索能力：输入 query，生成 query embedding，去 OpenSearch 召回 topK。验收标准：能返回相关 chunk 列表，而不是空结果。

接入 Infinity 精排。把召回结果送给 bge-reranker-v2-m3，重新排序后取前几条。验收标准：精排后结果相关性明显优于只靠召回。

实现问答接口。用 qwen3:14b 把“用户问题 + 精排后的上下文”生成最终回答。验收标准：能返回答案，并能带上引用 chunk 或来源文档。

实现引用与可追溯性。答案里至少返回 document_id、title、chunk_id、片段摘要。验收标准：用户能知道答案来自哪篇文档。

实现导入状态页。至少能看到文档当前处于 uploaded / parsing / indexed / failed 哪一步。验收标准：上传文档后，状态变化可追踪。

实现失败重试机制。解析失败、OCR 失败、embedding 失败、索引失败都要能单独重试。验收标准：失败后不用删库重来，可以按文档或按任务补跑。

实现删除与重建。文档删除后，要同步删除 OpenSearch chunk；文档重新上传新版本后，要能重建索引。验收标准：不会出现旧版本脏数据继续被检索到。

实现知识库管理。支持创建知识库、修改名称、查看文档列表、查看导入状态、删除文档。验收标准：最基本的管理后台能力可用。

实现会话问答。把 chat_session、chat_message 串起来，支持按知识库做连续问答。验收标准：同一会话多轮提问时，能保留上下文。

实现权限边界。第一版至少做到“用户只能访问自己有权限的知识库”。验收标准：不同用户不能互相看到不该看的文档与答案。

实现日志与监控。至少记录上传日志、任务日志、检索日志、模型调用耗时。验收标准：出问题时你能定位是卡在上传、解析、检索还是生成。

做一套验收样例。准备 5 到 10 份不同类型文档：DOCX、TXT、普通 PDF、扫描 PDF、图片。验收标准：这些样例都能完整跑通，且问答结果基本正确。

做性能基线。先量出单文档导入耗时、单次检索耗时、单次问答耗时。验收标准：你能说出当前系统的基线性能，而不是凭感觉。

做第一轮优化。常见优先级是：切块质量、召回 topK、精排数量、提示词模板、上下文长度。验收标准：同一批测试问题的命中率和回答质量有可见提升。

做运维脚本。至少补齐启动、初始化、健康检查、重建索引、查看日志的脚本或命令文档。验收标准：不是只有你自己会维护，别人也能接手。

准备上线前检查。确认数据备份、索引备份、模型可用、端口暴露策略、日志留存、磁盘容量。验收标准：系统重启后可以恢复，异常后可以回滚。
